# socks5-proxy

Асинхронный прокси-сервер на Python. Один порт принимает SOCKS5, HTTP-прокси и собственный протокол H2Mux: тип подключения определяется по первым байтам запроса. Для запуска достаточно стандартной библиотеки Python, сторонние пакеты не нужны.

## Возможности

- **SOCKS5:** TCP-подключения (`CONNECT`) и пересылка UDP (`UDP ASSOCIATE`); адрес назначения можно указать как IPv4, IPv6 или доменное имя. Команда `BIND` не поддерживается.
- **HTTP-прокси:** обычные HTTP-запросы и туннели `CONNECT` (например, для HTTPS). Поддерживаются тела запросов с `Content-Length` и `Transfer-Encoding: chunked`.
- **Авторизация (необязательная):** логин и пароль для SOCKS5 (username/password), HTTP (Proxy-Authorization: Basic) и H2Mux. Без обоих параметров сервер работает без авторизации.
- **Ответы на проверки подключения:** локально отвечает на известные HTTP-запросы проверки сети Microsoft, Apple, Firefox, GNOME, KDE и Ubuntu, а также на пути `/generate_204` и `/gen_204`.
- **H2Mux:** собственный протокол мультиплексирования TCP-туннелей через одно соединение, с фреймами и управлением потоком в стиле HTTP/2; до 8 одновременных потоков. Поддерживает специальный HTTP Upgrade `h2mux` для запросов к известным адресам проверки подключения. Это **не** универсальный сервер HTTP/2.

## Запуск

Нужен Python 3.8 или новее. Склонируйте репозиторий и выполните:

```bash
python3 socks5_proxy.py --host 127.0.0.1 --port 1080
```

По умолчанию сервер слушает `0.0.0.0:1080` **без авторизации**. Для подключения с других устройств укажите доступный сетевой адрес (например, `--host 0.0.0.0`) и включите авторизацию:

```bash
python3 socks5_proxy.py --host 0.0.0.0 --port 1080 --username myuser --password mypassword
```

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--host` | Адрес прослушивания | `0.0.0.0` |
| `--port` | TCP-порт | `1080` |
| `--username` | Логин для прокси | Не задан |
| `--password` | Пароль для прокси | Не задан |

`--username` и `--password` нужно указывать вместе. Все протоколы используют один и тот же TCP-порт; для SOCKS5 UDP-пересылка дополнительно открывает временный UDP-порт на время ассоциации.

## Примеры подключения

Без авторизации:

```bash
# SOCKS5 с разрешением доменного имени через прокси
curl --socks5-hostname 127.0.0.1:1080 http://example.com/

# HTTP-прокси
curl --proxy http://127.0.0.1:1080 http://example.com/

# HTTPS через HTTP CONNECT
curl --proxy http://127.0.0.1:1080 https://example.com/
```

С авторизацией:

```bash
curl --socks5-hostname 127.0.0.1:1080 --proxy-user myuser:mypassword http://example.com/
curl --proxy http://127.0.0.1:1080 --proxy-user myuser:mypassword https://example.com/
```

> **Безопасность:** сервер не шифрует соединение клиента с прокси. Basic-авторизация и пароль SOCKS5 передаются без TLS; не открывайте порт в интернет без дополнительной защиты (например, VPN или TLS-туннеля). Пароль, переданный через аргумент командной строки, может быть виден другим пользователям системы в списке процессов.
